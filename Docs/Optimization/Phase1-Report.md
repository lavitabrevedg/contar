# Contar 최적화 1차 결과

## 현재 상태

1차에서 시도한 `Digitalt SDF` 4096×4096 → 2048×2048 축소는 영어 글리프 렌더링 회귀가 발견되어 전면 폐기했다. 원인은 Alpha8 텍스처를 GPU로 축소한 뒤 잘못된 채널을 저장해 아틀라스가 단일 픽셀 값으로 채워진 것이다.

- 결함 에셋 표본: 최적화된 아틀라스의 검사 구간이 모두 `0xCD`
- 복원 검증: 백업 파일, Git 기준 파일, 복원 파일의 Git blob 해시가 모두 `c39ef8f095da8e255da87d32dfc101eac995cfe5`로 일치
- 현재 `Digitalt SDF.asset`: 원본 4096×4096, 33,614,538B
- 결함이 있던 변환 도구 제거
- 동적 NotoSansKR 프로파일링 캐시도 Git 기준 파일과 동일하게 정리

따라서 현재 플레이어 빌드에 반영된 신규 성능·용량 최적화는 없다. 이전에 보고한 폰트 에셋 및 메모리 감소 수치는 실제 렌더링 회귀가 있는 실패 실험의 수치이므로 최적화 성과로 사용할 수 없다.

## 유효하게 남은 작업

- 기준 프로파일 데이터 수집 도구
- 프레임, GC Alloc, 메모리, 드로우콜, 맵 생성, 솔버, 폰트, Android 빌드 크기 측정 코드
- Android Development 기준 빌드 데이터
- 프로젝트 구조와 패턴 적용 후보 감사 결과

`Deep_In_Space.wav`는 교체 예정이라는 요청에 따라 계속 제외한다.

## 기준 프로파일

- Unity: 6000.3.12f1
- Build Target: Android
- 런타임 표본: 워밍업 120프레임 후 600프레임
- 맵 생성: 20회
- 퍼즐 솔버: 13개 스테이지 × 10회
- 기준 Development APK: 85,067,988B
- 맵 생성 평균/P95: 1.5683ms / 2.6374ms
- 솔버 평균: 0.1907ms
- 기준 폰트 아틀라스 메모리: 33,555,328B

`after.json`은 파일 보존을 위해 남겼지만 `label`과 `buildResult`를 각각 `rejected-font-experiment`, `Rejected`로 표시했다. 해당 파일의 수치는 현재 프로젝트 상태나 성공한 최적화를 나타내지 않는다.

## 패턴 적용 판단

- 데이터 지역성: `PuzzleSolver`는 값 타입과 압축 상태 표현을 사용하고 있고, `MapGenerator`는 `BaseTile[,]` 격자를 사용한다.
- 공간 분할: 게임 보드의 2차원 격자 인덱스가 이미 공간 분할 역할을 한다.
- 더티 플래그: 매 프레임 반복되는 고비용 파생 계산이 확인되지 않았다.
- 오브젝트 풀: 맵 생성은 스테이지 로드 시 약 1.57ms이며, 풀의 상태 초기화와 상시 메모리를 정당화할 병목이 확인되지 않았다.

현재 최대 맵은 7×7, 49칸이므로 패턴 도입을 위한 대규모 리팩터링은 진행하지 않았다. 다음 최적화는 Android 실제 기기에서 Development Build와 Unity Profiler를 연결하고 CPU Timeline, GC.Alloc 호출 스택, 렌더링 병목을 확인한 뒤 진행해야 한다.

## 검증 규칙 보완

앞으로 폰트, 머티리얼, 스프라이트, 셰이더처럼 화면 출력에 영향을 주는 최적화는 다음 조건을 모두 통과해야 완료로 처리한다.

1. 데이터 구조와 참조 무결성 검사
2. 에디터 스크립트 컴파일
3. Development 빌드
4. 대표 화면의 Game View 직접 확인
5. 영문, 숫자, 특수문자 등 실제 사용 문자열 확인
6. 확인된 화면과 수치가 모두 정상일 때만 전후 성과 확정
